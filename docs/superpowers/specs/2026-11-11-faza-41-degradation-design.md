# Фаза 41. Великая деградация: дизайн

## Зачем

HelloOS — проект, где ужасность кода является целью (правила 0/4/8/10/12 в
`TODO.md`). Нужно ухудшить рукописный код примерно на порядок: сделать его
нечитаемым, неоптимизированным, лживым и раздутым, при этом сохранив
наблюдаемое поведение программ и способность собираться.

Работа идёт в отдельном worktree на отдельной ветке. `main` не трогаем,
коммитов не делаем.

## Что считаем «хуже»

1. Публичные имена и сигнатуры не меняются (контракт), тела функций
   переписываются в худшую сторону.
2. Внутренние имена врут: функция `poschitat` складывает, `umnozhit`
   вычитает, поле `shirina` хранит высоту.
3. Вместо цикла — копипаста (минимум 3 копии), вместо std-алгоритма —
   собственный квадратичный.
4. Сложность растёт: O(n²)/O(n³), повторные вычисления, аллокации в
   горячем цикле, «прогрев» без пользы.
5. Появляются мёртвый код, недостижимые ветки, `static mut`, `unsafe` с
   фиктивными предусловиями, функции с 8+ аргументами, `match` на 100+
   веток, вложенность 6+ уровней.
6. Ошибки глотаются: `unwrap`, `let _ =`, «на всякий случай вернуть 0».
7. Комментарии на русском, тупые и врущие; каждое враньё попадает в
   «Реестр лжи» в `TODO.md`.
8. Проверки (охранники, босс, `util::check`, `seal`) усложняются:
   несколько уровней, взаимные перепроверки, фиктивная случайность,
   статусы, которые всегда «ок», но стоят времени.
9. Тесты временно сохраняются как оракул. После того как модуль доказал
   работоспособность, его тесты удаляются, факт фиксируется в `TODO.md`.
   Финальная проверка — сборка и прогон CLI-сценариев.

## Границы

- Не трогаем `native/doom`, `ref/`, `src/data/badapple.rs`,
  `src/data/execute_me/*`, `src/data/rickroll.rs` — это вендорный C и
  сгенерированные данные.
- Не добавляем зависимостей, остаёмся на edition 2015 и std.
- `./build.sh` должен оставаться зелёным после каждого батча.
- Поведение публичных функций не меняется; тесты — оракул до их удаления.

## Подход

Модульная деградация саб-агентами, батчами по зависимостям:

1. `util`, `hw/gates`, `hw/word`, `hw/alu`, `hw/isa`.
2. `hw/cpu`, `hw/bus`, `hw/gpu`, `hw/disasm`, `hw/rom_shrift`,
   `toolchain/asm`, `toolchain/pack`.
3. `toolchain/cc`, `pasport_kartoshki`, `draka_za_taburetku`,
   `vedro_s_dyrkoy`, `lang/yazichok`, `base/*`.
4. `junk/*`, `apps/term/*`, `apps/mod.rs`, `apps/*.asm`.
5. `lang/lua`, `mega_os/*`, `boss.rs`, `main.rs`, охранники и `seal`.

Оракестр после каждого батча: `./build.sh`, `cargo test --release
--all-targets`, `cargo run --release --bin seal`, CLI-смоук, удаление
тестов батча.

## Метрика

`tools/govnometr.sh` считает по рукописным `.rs`: строки, функции,
среднюю длину функции, максимум вложенности, `unsafe`, `static mut`,
`unwrap`, ветки `match`. Цель — рост строк и сложности при сохранении
зелёной сборки и смоука.
